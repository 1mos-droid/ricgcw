<objective>
Implement a centralized service and data access layer (`src/services/`) that decouples Firestore mutations and queries from React UI components, provide complete test suites for each service, migrate key creation dialogs to use the service layer, and harden the global ErrorBoundary.

Decisions addressed:
- D-03: Create dedicated domain service modules under `src/services/` (`memberService.js`, `attendanceService.js`, `financialService.js`, `eventService.js`).
- D-04: UI components MUST NOT call `addDoc`, `updateDoc`, `deleteDoc`, or direct Firestore primitives inline; they must call the dedicated service layer methods.

Purpose: Prevent duplicated inline Firestore queries, ensure consistent schema validation, eliminate silent failures, and protect UI views from crash cascades.
Output: Dedicated service modules, accompanying unit tests, refactored creation dialogs, and hardened ErrorBoundary.
</objective>
