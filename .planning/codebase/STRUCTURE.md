## Key File Locations

**Entry Points:**

- `src/main.jsx`: Sentry error logging and React application initialization.
- `src/App.jsx`: Global provider tree setup.
- `src/routes/Router.jsx`: Complete route table and navigation authorization guards.
- `functions/index.js`: Serverless backend entry point.

**Configuration:**

- `vite.config.js`: Dev server, PWA Workbox caching, vendor chunking, Vitest runner setup.
- `eslint.config.js`: ESLint rules and parser configuration.
- `firebase.json`: Hosting and function deploy rules.
- `firestore.rules`: Security rules for Cloud Firestore collections.
- `src/theme.jsx`: MUI palette, typography, and component overrides.

**Core Logic:**

- `src/context/AuthContext.jsx`: Identity sync between Appwrite and Firestore.
- `src/context/WorkspaceContext.jsx`: Multi-workspace switching and identity mimicry.
- `src/utils/syncDepartments.js`: Automatic age-based department migration engine.

**Testing:**

- `src/setupTests.js`: Test environment mocks (matchMedia, localStorage).
- Unit and component tests co-located next to target source files (`*.test.js`, `*.test.jsx`).

## Naming Conventions

**Files:**

- React Components & Pages: PascalCase with `.jsx` extension (e.g., `Dashboard.jsx`, `MemberDetailsDialog.jsx`, `SmartFilterBar.jsx`).
- Utility Modules & Configs: camelCase with `.js` extension (e.g., `dualCustody.js`, `safetyTokens.js`, `appwriteConfig.js`).
- Test Files: Co-located with suffix `.test.js` or `.test.jsx` (e.g., `dualCustody.test.js`, `Layout.test.jsx`).
- Style Files: PascalCase or lowercase with `.css` extension (e.g., `index.css`, `Dashboard.css`).

**Directories:**

- Plural lowercase or hyphenated lowercase: `components/`, `context/`, `hooks/`, `pages/`, `routes/`, `utils/`, `atoms/`, `molecules/`, `organisms/`.

## Where to Add New Code

**New Feature Page:**

- Create page component in [`src/pages/MyFeature.jsx`](file:///home/admin/Projects/ricgcw/src/pages/).
- Create test file in [`src/pages/MyFeature.test.jsx`](file:///home/admin/Projects/ricgcw/src/pages/).
- Register lazy route and permission guard in [`src/routes/Router.jsx`](file:///home/admin/Projects/ricgcw/src/routes/Router.jsx).
- Add navigation item in [`src/components/Layout.jsx`](file:///home/admin/Projects/ricgcw/src/components/Layout.jsx#L73) and [`src/components/layout/SidebarNav.jsx`](file:///home/admin/Projects/ricgcw/src/components/layout/SidebarNav.jsx).

**New UI Component:**

- Determine Atomic Design level:
  - Primitive button/input/badge → [`src/components/atoms/`](file:///home/admin/Projects/ricgcw/src/components/atoms/)
  - Form row / composite filter → [`src/components/molecules/`](file:///home/admin/Projects/ricgcw/src/components/molecules/)
  - Complex self-contained widget → [`src/components/organisms/`](file:///home/admin/Projects/ricgcw/src/components/organisms/)
- Co-locate corresponding unit test alongside the component.

**Utilities & Domain Logic:**

- Pure functions, algorithms, or API wrappers belong in [`src/utils/`](file:///home/admin/Projects/ricgcw/src/utils/).
- Every utility must have a corresponding test suite in `src/utils/<name>.test.js`.

**Backend Cloud Function Endpoint:**

- Add route or trigger in [`functions/index.js`](file:///home/admin/Projects/ricgcw/functions/index.js).
